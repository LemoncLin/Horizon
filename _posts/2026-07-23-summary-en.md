## [PyPI Blocks Uploads to Releases Older Than 14 Days](https://simonwillison.net/2026/Jul/23/seth-larson/#atom-everything) ⭐️ 8.0/10

The Python Package Index (PyPI) now rejects new file uploads to releases that are older than 14 days. This policy change was implemented to prevent supply chain poisoning attacks on long-stable packages if publishing credentials are compromised. This update significantly enhances the security of the Python ecosystem by mitigating risks associated with compromised API tokens and workflows. It directly impacts developers and maintainers by restricting retroactive modifications to established releases, thereby reducing the attack surface for supply chain vulnerabilities. The restriction applies specifically to preventing the addition of malicious files to old, stable releases rather than blocking new release creation. While no abuse has been reported yet, this measure addresses a technical possibility where attackers could exploit stolen credentials to poison widely used libraries.

rss · Simon Willison · Jul 23, 04:50

**Background**: Supply chain attacks in the Python ecosystem often involve compromising publishing tokens or CI/CD workflows to inject malicious code into popular packages. Recent incidents, such as the LiteLLM breach, highlight how attackers can use legitimate stolen credentials to bypass integrity checks. PyPI's Trusted Publishing feature aims to eliminate long-lived API tokens, but this new upload restriction adds another layer of defense against retroactive tampering.
